## In KAIRA master, switched off or not measured

These changes reached KAIRA master with the opt-integ-20261111 merge (7aa9bee, 2026-11-11) and the rd2-integ-20261112 merge (048d4fe, 2026-11-13). They are built and tested on CPU and fake-CUDA, and reviewed. The switches stay off by default until a GPU A/B shows a gain.
- **WEX4 first-read SHA-256 off the serial path.** A demand batch hashes its due records in parallel. A record that fails its hash is refused for the rest of the process. Whole and striped reads are tracked separately. Since 048d4fe the GPU-direct fill also hashes a RAM record-cache hit before it serves it, as the batch path does (cfac79f; a record that passed costs one seen-bit load, a failed one leaves the cache).
- **Hash pool** (`V4_WEX_SHA_ASYNC=1`, ef3df71 and edcfc38). Host reads and prefetch batches are hashed on 4 threads while they decode; a record is published only after its hash passes. **Measured neutral: start to first token -0.2%, decode +0.5%, so it stays off.**
- **Integrity lane** (cb225b3). `tools/wex4_verify` checks a WEX4 file and prints its root (used on the Qwen3.8 copies on 2026-11-13). qwen38 can hash each WEX4 record at its first read with `COLI_WEX_VERIFY=1` (default 0, not set in the profile). Under a pinned `COLI_WEX_ROOT` a container that is not WEX4 is refused: V4 falls back to the safetensors, qwen38 stops (this refusal is active in `v41gpu`, whose root is pinned).
- **Demand reads striped over the primary and the mirror** (`V4_WEX_STRIPE=1`, default off). Each record is split at a 4096-aligned cut weighted like `COLI_WEX_WEIGHTS`, and the first-read hash still covers every byte. Qwen3.8 has the same switch for lone decode misses. **Measured on V4.1: -8.72% ± 2.66% (ABBA, 3 prompts, identical tokens), so it stays off.** The extra requests queue behind prefetch reads; the lever is giving demand reads priority, not splitting them. (`V4_WEX_SUBREADS`, which is on, splits a record into overlapped reads in the same queue instead.)
- **Pre-Ampere fallback in `wex_cuda.cuh`.** Below sm_80, `cp.async` becomes a plain load and store, so the WNR3 GPU decoder builds for Pascal and Turing. It has not run on such a GPU yet.

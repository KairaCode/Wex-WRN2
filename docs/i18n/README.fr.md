# WEX (résumé en français)

Résumé du [README anglais](../../README.md) du 2026-11-15. Le README anglais fait foi : en cas de différence entre les deux textes, c'est l'anglais qui prévaut. Cette traduction n'a pas été écrite par un locuteur natif ; les corrections sont les bienvenues, par une issue ou une pull request.

- **Ce que c'est.** WEX est une famille de formats de conteneur pour les experts des modèles Mixture-of-Experts : un fichier de records alignés sur 4096 octets, un par routed expert, que le moteur lit depuis un disque NVMe en une seule lecture pendant qu'il génère. WEX4 ajoute une header page et un index avec le SHA-256 de chaque record ; WNR3 est le codage rANS sans perte des records. WEX4 (version de format 4.0) et WNR3 (v1) sont figés ; le code est l'implémentation de référence, de niveau recherche et conçue d'abord pour Windows.
- **Ce qui tourne aujourd'hui** (résumé du 2026-11-13). DeepSeek V4.1 REAP-192 lit un WEX4 à records WNR3 (0.854 de la taille non compressée), Qwen3.8-Flash-Next un WEX4 à records MXFP4 non compressés (RAW) ; tous deux depuis deux disques NVMe (U: et C:, lectures réparties 38/62). État à jour : [STATUS.md](../../STATUS.md).
- **Comment l'essayer.** `bash scripts/check_all.sh` compile et lance les vérifications sur CPU (tests des formats, lecteurs et convertisseurs WEX4, vecteurs de conformité, décodeur WNR3 rapide) et la vérification du dépôt, sans GPU ni modèle ; la dernière ligne est `all checks passed`. Il faut un CPU x86-64 avec AVX2 ou un CPU ARM 64 bits, `bash`, un `gcc` GNU et Python 3 (bibliothèque standard seulement). La CI l'exécute sous Linux (x86-64 et ARM64), macOS (Apple silicon) et Windows.

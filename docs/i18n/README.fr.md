# WEX (résumé en français)

Résumé du [README anglais](../../README.md) du 2026-11-26. Le README anglais fait foi : en cas de différence entre les deux textes, c'est l'anglais qui prévaut. Cette traduction n'a pas été écrite par un locuteur natif ; les corrections sont les bienvenues, par une issue ou une pull request.

- **Ce que c'est.** WEX est une famille de formats de conteneur pour les experts des modèles Mixture-of-Experts : un fichier de records alignés sur 4096 octets, un par routed expert, que le moteur lit depuis un disque NVMe en une seule lecture pendant qu'il génère. WEX4 ajoute une header page et un index avec le SHA-256 de chaque record ; WNR3 (codec 5) et WNR4 (codec 8 : types MX, NV, GG et I4, 32 voies rANS par tile pour un décodage parallèle sur GPU) sont les codages rANS sans perte des records. WEX4 (version de format 4.0) avec WNR3/WNR4 est en production ; le code est l'implémentation de référence, de niveau recherche et conçue d'abord pour Windows.
- **Sans perte, ce n'est pas une quantification.** Comme avec un ZIP, on retrouve les mêmes poids que ceux qui ont été enregistrés : les mêmes octets ou, avec le zéro canonique, les mêmes nombres (un zéro écrit « -0 » revient écrit « +0 »). WEX n'arrondit, ne quantifie et n'élague rien. La précision des poids à 4 bits se perd avant WEX : dans la quantification faite par l'éditeur du modèle ou par des tiers (AMD pour Qwen3.8), dans l'élagage REAP de DeepSeek V4.1 fait par un tiers, et dans notre requantification des fichiers Sage-S2.1-Flash publiés. Comment le vérifier : [Check it yourself](../../README.md#check-it-yourself).
- **Ce qui tourne aujourd'hui** (résumé du 2026-11-26). DeepSeek V4.1 REAP-192 utilise WEX4 avec WNR3-CZ (123,3 Go, 0,854) et WNR4-MX (122,9 Go, 0,851, CUDA feature 64) sur deux disques NVMe (répartition 38/62) ; Qwen3.8-Flash-Next utilise WEX4 MXFP4 (RAW 64,3 Go en miroir + WNR4-MX 56,8 Go), WEX4 + WNR4-I4 int4-g64 (`G=4` production 54,0 Go / 0,794 avec CUDA feature 128 dans `qwen38`, 0,027 ms noyau ; `G=32` archive 53,3 Go / 0,784) et WEX4 + WNR4-GG GGUF 2 bits (33,4 Go, 0,957). État à jour : [STATUS.md](../../STATUS.md).
- **Comment l'essayer.** `bash scripts/check_all.sh` compile et lance les vérifications sur CPU (tests des formats, tests CPU WNR4, lecteurs et convertisseurs WEX4, vecteurs de conformité, décodeur WNR3 rapide) et la vérification du dépôt, sans GPU ni modèle ; en cas de succès, la dernière ligne est `all checks passed`, avec le code de sortie 0. Les prérequis sont dans la section [Try it in ten minutes](../../README.md#try-it-in-ten-minutes) du README. La CI l'exécute sous Linux (x86-64 et ARM64), macOS (Apple silicon, avec GNU gcc et avec Apple clang) et Windows ; les sanitizers, le fuzzing et les lecteurs en Go et en Rust (qui décodent aussi WNR4 GG/I4) sont des jobs à part.

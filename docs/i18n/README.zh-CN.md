# WEX（简体中文简介）

本文是英文 [README](../../README.md) 的简短摘要，日期为 2026-11-26。英文 README 是参考文本：两者不一致时，以英文版为准。本译文并非由母语者撰写，欢迎指正（提交 issue 或 pull request）。

- **是什么。** WEX 是一系列容器格式，用于存放混合专家（Mixture-of-Experts）模型的专家（expert）：一个文件由按 4096 字节对齐的 record 组成，每个 routed expert 一个 record，引擎在生成过程中通过一次读取将其从 NVMe 读入。WEX4 增加了 header page 和索引（index），其中含有每个 record 的 SHA-256；WNR3（codec 5）和 WNR4（codec 8：含 MX、NV、GG、I4 四种类型，每个 tile 含 32 条 rANS 通道用于 GPU 并行解码）是 record 的无损 rANS 编码。WEX4（格式版本 4.0）与 WNR3/WNR4 已投入使用；这里的代码是参考实现，属于研究级别（research-grade），并且优先面向 Windows。
- **无损，不是量化。** 就像 ZIP 一样，读回的就是存入时的同一组权重：字节完全相同；或者在使用规范零（canonical zero）时，数值完全相同（写作“-0”的零读回时写作“+0”）。WEX 不做任何舍入、量化或剪枝。4 位权重的精度在 WEX 之前就已损失：在模型发布者或第三方所做的量化中（Qwen3.8 由 AMD 量化），在第三方对 DeepSeek V4.1 所做的 REAP 剪枝中，以及在我们对所发布的 Sage-S2.1-Flash 文件所做的重新量化中。如何验证：见 README 的 [Check it yourself](../../README.md#check-it-yourself) 一节。
- **目前运行的内容**（2026-11-26 的摘要）。DeepSeek V4.1 REAP-192 使用 WEX4 + WNR3-CZ（123.3 GB，0.854）与 WNR4-MX（122.9 GB，0.851，CUDA feature 64），分布在两块 NVMe 硬盘上（38/62 分配）；Qwen3.8-Flash-Next 使用 WEX4 MXFP4（RAW 64.3 GB 双盘镜像 + WNR4-MX 56.8 GB）、WEX4 + WNR4-I4 int4-g64（`G=4` 生产 54.0 GB / 0.794，`qwen38` CUDA feature 128，0.027 ms 内核延迟；`G=32` 归档 53.3 GB / 0.784）以及 WEX4 + WNR4-GG 2-bit GGUF（33.4 GB，0.957）。最新状态见 [STATUS.md](../../STATUS.md)。
- **如何试用。** `bash scripts/check_all.sh` 会编译并运行 CPU 检查（格式测试、WNR4 CPU 测试、WEX4 读取器和转换器、一致性测试向量、快速 WNR3 解码器）以及仓库检查，不需要 GPU，也不需要模型；成功时最后一行是 `all checks passed`，退出码为 0。前提条件见 README 的 [Try it in ten minutes](../../README.md#try-it-in-ten-minutes) 一节。CI 在 Linux（x86-64 和 ARM64）、macOS（Apple silicon，分别使用 GNU gcc 和 Apple clang）和 Windows 上运行它；sanitizer、模糊测试（fuzzing）以及 Go 和 Rust 读取器（现均支持 WNR4 GG/I4 解码）是单独的 CI 作业。

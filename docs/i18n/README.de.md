- **Was es ist.** WEX ist eine Familie von Containerformaten für die Experten von Mixture-of-Experts-Modellen: eine Datei aus an 4096 Byte ausgerichteten Records, ein Record pro Routed Expert, den die Engine während der Generierung mit einem einzigen Lesezugriff von NVMe liest. WEX4 fügt eine Header Page und einen Index mit dem SHA-256 jedes Records hinzu; WNR3 ist die verlustfreie rANS-Kodierung der Records. WEX4 (Formatversion 4.0) und WNR3 (v1) sind eingefroren; der Code ist die Referenzimplementierung, auf Forschungsniveau und zuerst für Windows gebaut.
- **Was heute läuft** (Stand 2026-11-13). DeepSeek V4.1 REAP-192 liest einen WEX4-Container mit WNR3-Records (0.854 der unkomprimierten Größe), Qwen3.8-Flash-Next einen WEX4-Container mit unkomprimierten MXFP4-Records (RAW); beide von zwei NVMe-Laufwerken (U: und C:, Lesezugriffe im Verhältnis 38/62 aufgeteilt). Aktueller Stand: [STATUS.md](../../STATUS.md).
- **Ausprobieren.** `bash scripts/check_all.sh` baut und startet die CPU-Prüfungen (Tests der Formate, WEX4-Leser und -Konverter, Konformitätsvektoren, der schnelle WNR3-Decoder) und die Prüfung des Repositorys, ohne GPU und ohne Modell; die letzte Zeile ist `all checks passed`. Nötig sind eine x86-64-CPU mit AVX2 oder eine 64-Bit-ARM-CPU, `bash`, ein GNU-`gcc` und Python 3 (nur die Standardbibliothek). Die CI führt es unter Linux (x86-64 und ARM64), macOS (Apple silicon) und Windows aus.

# scripts/

**Current.** Build and check scripts that exist only in this repository. They used to sit among the mirrored files; `c/` now holds only the engine-side WEX files.

- `check_all.sh`: every check of this repository that needs no GPU, no model and no engine tree, in one command: `check_repo.py` (self-test and check), the three standard-library tests below, `build_cpu_check.sh` and `wex4/build_and_test.sh`. Run `bash scripts/check_all.sh` from anywhere; last line on success: `all checks passed`. It is what CI runs. `CC` names the C compiler of the two build scripts (default `gcc`; CI also runs the whole check with `CC=clang` on Linux, in the `linux-tsan` job) and `WEX_CFLAGS` adds flags to every compiler call of theirs; the `linux-sanitizers` CI job puts its sanitizer flags there and preloads the ASan runtime, because the tests load the libraries into Python (the exact flags and options are in `.github/workflows/ci.yml`).
- `build_cpu_check.sh`: the CPU self-test of `c/`, no GPU and no real model. It builds and runs `c/tests/test_wex_format.c` and `c/tests/test_wex4_verify.c` (the WEX4 checker `c/tools/wex4_verify.c` on small synthetic WEX4 files: an intact file passes with the expected root, changed records, padding, blobs, index and header page fail; it prints one summary line), compiles `c/tools/wex4_verify.c` alone, compiles the WNR3 encoder DLL and the CPU stand-in helper, then builds a WEX1, WNR3-CZ bins and a WNR3-CZ container from `fixtures/v41-tiny`. Run `bash scripts/build_cpu_check.sh` from the repository root with MSYS2 UCRT64 or MINGW64 `gcc` on `PATH`; last line on success: `WNR3 CPU check passed`. The summary line `"gate_failures": 144` above it is not an error: it counts the matrices (48 records x 3) of the tiny fixture on which ceil-form was not used. Output goes to `out/cpu-check/` (git-ignored). With a colibri engine `c/` folder (one that holds `expert_store_registry.c` and the engine headers) as first argument it also builds and runs `c/tests/test_expert_store_wex.c`, which needs engine headers.
- `sanitize_c.sh`: the C test executables under ThreadSanitizer or MemorySanitizer, `bash scripts/sanitize_c.sh tsan` or `bash scripts/sanitize_c.sh msan`; last line on success: `tsan run passed` or `msan run passed`. Linux with clang only (the MSYS2 clang has neither sanitizer); `tsan` also needs the OpenMP runtime of that clang with its Archer tool (Ubuntu: `libomp-N-dev`). It first builds two controls: a file with a deliberate data race or a read of an uninitialised byte, which the sanitizer must report, and for `tsan` a correct OpenMP loop, which must give no report. Then it runs `c/tests/test_wex_format.c` (`msan` only), `c/tests/test_wex4_verify.c`, `c/tools/wex4_verify.c` on 8 threads over the valid conformance vectors and a WEX4 file of 4 synthetic WNR3 records, and the three harnesses of `wex4/fuzz/` on their seeds and on that file, where a record has 192 weight streams, which the fast decoder splits into 4 OpenMP tasks. `tsan` builds with `-fopenmp`, `msan` without it. Not covered: the libraries that the other checks load into Python, because both sanitizers need the whole process instrumented. It is what the `linux-tsan` and `linux-msan` CI jobs run (clang 18 on ubuntu-24.04, x86-64); no report from either on 2026-11-14. Output goes to `out/tsan/`, `out/msan/` and `wex4/fuzz/out/` (git-ignored).
- `verify_wex1.py`: byte check of a WEX1 / WEX2 / WEX3 container against the safetensors checkpoint it was built from: `python -I scripts/verify_wex1.py --model-dir DIR --wex FILE [--stride N]`. It rejects a WNR2 container (check that with `archive/nr2/check_container.c` or `archive/nr2/check_all.py`); WNR3 and WEX4 are outside its scope (for WEX4: `python -I wex4/wex4.py verify FILE`).
- `test_verify_wex1.py`: its test on a synthetic model, `python -I scripts/test_verify_wex1.py`.

The repository check, [`../check_repo.py`](../check_repo.py), is at the root. The GPU builds are in [`../integration/build/`](../integration/README.md); the WEX4 tests are run by [`../wex4/build_and_test.sh`](../wex4/README.md).

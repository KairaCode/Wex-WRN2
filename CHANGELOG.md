# Changelog

Format-level changes only, newest first: container versions, record codecs, flags and ids, the helper's feature bits, the tools that write or convert files, and the date a format went into or out of production. Engine tuning is in [STATUS.md](STATUS.md), its measurements in [docs/BENCHMARKS.md](docs/BENCHMARKS.md).

Entries are dated; commit ids of the maintainer's engine tree, which is not public, are not given. The history of this repository starts on 2026-11-12, when the earlier work (from 2026-11-09) was gathered into one commit; an entry is identified by its date. There are no release tags yet. Specification versions: WEX4 4.0 ([docs/WEX4-SPEC.md](docs/WEX4-SPEC.md)) and WNR3 v1 ([docs/WNR3-SPEC.md](docs/WNR3-SPEC.md)); WEX1 to WEX3 and WNR2 are described in [docs/WNR2-REFERENCE.md](docs/WNR2-REFERENCE.md). The entries before 2026-11-09 come from the timeline and measurement sections of [docs/reports/wnr2-history-20261110.md](docs/reports/wnr2-history-20261110.md) and were not re-verified.

## 2026-11-14

- **2026-11-14** Tooling, no format byte changed: `scripts/build_cpu_check.sh` and `wex4/build_and_test.sh` take the C compiler from `CC` (default `gcc`, so nothing changes where it is not set), and `wex4/fuzz/run.sh --replay` does the same. CI gains a `macos` job (macos-15, Apple silicon) that runs `scripts/check_all.sh` with a Homebrew GNU gcc in `CC`; no source file needed a change for macOS. Not tried: Apple clang with `libomp`, an Intel Mac.
- **2026-11-14** Tooling, no format byte changed: `scripts/build_cpu_check.sh` and `wex4/build_and_test.sh` append `WEX_CFLAGS` (empty by default) to every compile and link; CI gains a `linux-sanitizers` job that runs `scripts/check_all.sh` under AddressSanitizer and UndefinedBehaviorSanitizer.
- **2026-11-14** WEX4 conformance vectors, no format change and no verdict of an existing vector changed: 48 more invalid files in `wex4/vectors/invalid/` (94 in all, 112 manifest rows). 25 are made from `generic.wex4` and 23 from `tiny2-cz-upgraded.wex4`, the first hostile files with blobs, an expert grid and WNR3 records. They add the reject classes `WEX4_E_INDEX`, `WEX4_E_BLOB` and `WEX4_E_DATA`, which no vector had, and a flipped bit in the index, in a record and in a blob with the hash left alone. `wex4/test_wex4.py` builds them (`test_hostile`, `test_hostile_experts`); the C reader (fast and reference decoder) and the Python reader refuse all of them.
- **2026-11-14** Tooling, no format byte changed: `wex4/fuzz/` holds three libFuzzer harnesses (`fuzz_wex4_file.c` for the reader of `c/wex4.h`, `fuzz_wnr3_record.c` for the reference and the fast WNR3 decoder, which must agree, `fuzz_wex4_verify.c` for `c/tools/wex4_verify.c`), their seeds from the conformance vectors and `run.sh`; the workflow `.github/workflows/fuzz.yml` builds them with AddressSanitizer and UndefinedBehaviorSanitizer and runs each for 60 seconds.
- **2026-11-14** Tooling, no format byte changed: `wex4/build_and_test.sh` passes `-march=haswell` to the fast WNR3 CPU decoder on x86 only; on any other CPU the same source builds its scalar kernel (`WEX4_MARCH` overrides the choice, and `WEX4_MARCH=` builds the scalar kernel on x86). CI gains a `linux-arm` job (ubuntu-24.04-arm) that runs `scripts/check_all.sh`. No NEON kernels yet.
- **2026-11-14** Tooling, no format byte changed: the sync map is now `sync-map.tsv`, its line 1 `# source_commit <sha> <date>`; `check_repo.py` compares `c/` with another tree through `--source <TREE>` (the old option name still works) and no longer requires `STATUS.md` and `integration/README.md` to name the recorded commit. The three loader patches in `integration/` are now named `engine-*.patch` (same bytes, same suffixes). Files under `c/` may be changed by pull requests like any other code. The pages name the maintainer's engine tree by date instead of by commit id.

## 2026-11-13

- **2026-11-13** Licence, no format byte changed: the repository is under the Apache License 2.0 (`LICENSE`, `NOTICE`, `THIRD_PARTY_NOTICES.md`). Source files outside `research/` start with an SPDX header; the files derived from colibri (listed in `NOTICE`) name their source and their modification; `check_repo.py` gains the `licence` check. The headers of the files under `c/` (37 after the sync below) still have to reach the maintainer's application tree.
- **2026-11-13** Sync with the maintainer's engine tree of 2026-11-13, 37 files under `c/`. New checker `c/tools/wex4_verify.c`: one read-only pass over a WEX4 file on N threads (OpenMP, 8 by default) that checks the header page, the index and every blob and record against its SHA-256, and that padding is zero, then prints `COLI_WEX_ROOT=<root>`; exit 0 pass, 1 mismatch, 2 not WEX4. Its test `c/tests/test_wex4_verify.c` and the in-memory WEX4 fixture `c/tests/wex4_fixture.h` come with it. `c/qwen38_wex.h` hashes each WEX4 record at its first read with `COLI_WEX_VERIFY=1` (default 0, and independent of the root, unlike the DeepSeek store) and, under a pinned `COLI_WEX_ROOT`, refuses a container that is not WEX4; the DeepSeek store refuses it too and reads the safetensors instead (W06). New read-only drive probe `c/tools/wexio_probe.py` (Windows). The CPU stand-in helper `c/tests/fake_wex_cuda.c` reports feature 8 with `FAKE_WEX_BATCH_DEVICE=1`. The four new files carry the same licence header as the other files under `c/`. WEX4 4.0, no format byte changed.
- **2026-11-13** Read path of the DeepSeek store, in the engine since the merge of branch rd2-integ-20261112; no format byte changed, every switch off by default: `V4_WEX_SUBREADS=N` reads each drive's part of a record as N overlapped sub-reads and, with a mirror, cuts host reads and batches across both drives; `V4_PREWARM_BATCH=1` fills the VRAM tier through the batched GPU-direct decode, two batches deep; `V4_WEX_SHA_ASYNC=1` runs the first-read SHA-256 on a pool of 4 threads, a record being published only after its hash passes; a RAM record-cache hit in the GPU-direct fill is hashed before it is served, as the batch path does. The first two are installed in the `v41gpu` profile; the hash pool is not ([STATUS.md](STATUS.md)). WEX4 4.0.
- **2026-11-13** WEX4 conformance vectors: `wex4/vectors/` with `MANIFEST.tsv` (7 valid files with their roots, 46 invalid, one legacy WEX3 file whose upgrade must give a valid one byte for byte); WEX4-SPEC section 17 (conformance). WEX4 4.0, no format change.
- **2026-11-13** Repository layout, no format byte changed: `nr2/` and `bench/` moved to `archive/`; the `next/` stub removed (no mirrored file names it any more); the integration guide of 2026-11-09 became a dated report and `docs/COLIBRI-INTEGRATION.md` a guide for WEX4; the measurements moved from `STATUS.md` to `docs/BENCHMARKS.md`; `scripts/check_all.sh` runs every CPU check.
- **2026-11-13** Sync with the maintainer's engine tree of 2026-11-12: `qwen38_wex.h` names a WEX4 container WEX4 in its log and unpins an MXFP4 record slab before it resizes it (for `QT_GPU_MISS=2`); `test_qwen38_mxfp4.py` checks the WEX1 log name; comments only in `wex4.h` and `build_nr3.py`. No format byte changed.
